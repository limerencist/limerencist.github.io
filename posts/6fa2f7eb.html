Metrics 初試

更新於2026-05-22|devops
|字數統計:1.7k|閱讀時間:6分鐘|瀏覽量:

  之前在上家公司搞監控服務的時候，項目上有需要 exporter ，恰好負責這部分程序的同事和我坐在一起，本想著跟他學習一下這塊代碼的，後來忙著其他事就沒顧上。現在又搞上監控了，趁著有時間趕緊學習一下，雖說不能是實際的業務代碼，至少了解一些基本的概念，以備不時之需。

  其實說概念多少也是知道一些的，就是暴露出指標隨時間而變化的更新過程，然後讓其他程序獲取，來完成特定的監控需求。否則，沒有數據，監控也無從談起，而我比較好奇的是指標的修改過程究竟如何實現。本以為十分複雜，沒想到也就是基於 Promethues 的框架來填充內容。當然，也可能是我只是冩了 demo 看看效果，並沒有實際的業務。

程序編冩

定義指標

  傳說在很久很久以前， metrics 的世界裡，有著四天王，木偶獸鋼鐵海龍獸小丑皇……啊不是，串臺了，是下面 4 個：

  • Counter（計數器）：只增不減（如請求數、錯誤數）;
  • Gauge（儀表盤）：可增可減（如內存使用量、隊列長度）;
  • Histogram（直方圖）：對測量值進行分佈統計（如延遲分桶）;
  • Summary（摘要）：客戶端計算的分位數（如 P99 延遲）;

計數工作

  簡單說下測試的業務流程：

  1. 開啟了一個獨立的協程後臺運行；
  2. 隨機任務：每次循環從 jpg, png, webp 中隨機選一個；
  3. 隨機耗時：time.Sleep(rand.Intn(5000)) 模擬 0 到 5 秒的處理延遲；
  4. 隨機大小：rand.Intn(10485760) 產生 0 到 10MB 的隨機數值；
  5. 任務進行時，調整指標裡的數據；

  一個完整調用四天王的生命週期如下：

  1. 開始：Gauge +1；
  2. 記錄起點：start := time.Now()；
  3. 處理：Sleep；
  4. 結束：duration := time.Since(start).Seconds() 計算耗時；
  5. 採樣：Gauge -1，Counter +1，把耗時丟給 Histogram，把圖片大小丟給 Summary；

main函數

  默認的 Registry 會自動包含 Go 運行時的默認指標（如內存、協程數等），我這裡為了接口頁面裡看得清楚，就自定義 Registry 只收集上面定義的指標。其他就是常規操作，暴露 / 提示服務正常（不屑也沒事），關鍵把 /metrics 暴露出來就行。

訪問接口

  先訪問 / 路由；

  再訪問 /metrics，注意讓子彈先飛一會兒，不是，讓程序運行一會兒，或者每隔一秒手動刷新一次，會看到數據不停的刷新；

查詢指標

用 Counter 查 QPS

用 Gauge 查實時值

用 Histogram 查延遲

  查詢 Histogram 的 image_service_duration_seconds 時，需要注意 prometheus 程序的啟動參數中，必須加入 -enable-feature=native-histograms 後才能查詢。否則，只有 image_service_duration_seconds_bucket 能查詢到數據，image_service_duration_seconds_bucket 則是因為目前代碼裡採用兼容模式，手動設置了 Buckets。

用 Summary 查分位數

  當有了數據之後，通過各式各樣的 PromQL 可以把查到的數據玩出花來，這裡這是顯示一下效果，具體還得根據實際的業務需求作出調整。

總結

  完成 metrics 之後，描述 exporter 就容易多了：簡單理解的話，exporter 也是一種 metrics 接口，只不過是數據來源不是自身程序提供的，而是通過另外的 SDK、接口或其他方式獲取到的。

  我們來想想 node-exporter 和 mysql-exporter。前者用來採集服務器上 CPU、內存、磁盤、網絡等信息，服務器雖然有這些信息，但是不去拿，就獲取不到，所以得冩個程序去定期採集；同理，後者是監控 mysql 的， mysql 本身提供了可以監控的指標，比如 主從狀態 啊， binlog position 啊什麼的，但是無法直接獲取，就需要 exporter 這個中介把這些信息轉換成通用且符合標準的數據。

 簡而言之，程序本身可控的，直接暴露 metrics 接口；碰到第三方，那就派出 exporter 做個媒婆，把寂寞獨立的兩顆心串一串，串一株幸運草，串一個同心圓……（不好意思，串著串著又串錯臺暴露年齡了）。然後就可以方便 prometheus 讀取，進一步從 grafana 上展示出來，從而實現監控和後續的分析、告警等操作。
