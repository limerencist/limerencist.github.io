加需求！獲取構建分支!

更新於2026-06-26|dev
|字數統計:2k|閱讀時間:8分鐘|瀏覽量:

  過了這麼久，仍然在和機器人打交道，不過這次的需求跟 Jenkins 有關：根據站點名稱和任務類型，獲取對應任務中配置的分支信息。雖說這個功能在 Jenkins 頁面上就能看到，但是一來 Jenkins 也不是每個研發都能訪問的，如果開發想確認一下當前項目使用的分支，還得找我幫忙；二來，就算我每天閒得沒事幹，每次打開頁面也要找對應的任務才能看流水線裡面配置的分支，確實也挺麻煩。所以，我決定把這個功能加到機器人裡，讓開發可以自己獲取到這些信息，順便給自己減負。

  這個需求說白了，其實也就是個查詢接口，Jenkins 本身提供了多種展現方式。通過請求正確的 API 獲取到內容後，按一定的格式解析其中的內容，返回到 TG 的聊天消息中就成。

GetBranch

  主線流程如下：

  1. 獲取 Jenkins 配置；
  2. 解析參數，獲取任務類型和站點別名；
  3. 遍歷站點別名，獲取對應站點信息（主要的一個判斷就是查詢參數中的任務在對應站點中是否存在：如果某個站點中不存在該任務，則返回提示信息並跳過該站點，繼續查詢下一個站點）；
  4. 查詢 Jenkins API 獲取信息並解析，將結果返回到 TG 的聊天消息中；
  5. 實際編寫代碼過程中，臨時發現前端項目除了分支信息外，研發有時候還需要知道構建命令，就額外查詢一次 NPM 構建命令並返回（和獲取分支大同小異，就是解析的內容不同）；

FetchJenkinsData

  不管是獲取分支還是獲取構建命令，都是通過 Jenkins API 獲取數據，所以需要一個通用的函數來處理 Get 請求。

GetSiteAliases

  獲取站點別名，支持多個站點，可以是指定的內容（比如下面的 a系、t系），也可以用逗號分隔（比如A1，A3，T4）。同時考慮到輸入法問題，兼容中英文的逗號分隔符。

ExtractBranch

  獲取分支時，並沒有直接獲取 pipeline 的信息，而是請求 /api/json 接口查看最後一次構建的信息，從中獲取分支信息；考慮到手動解析返回的結果比較麻煩，就用 gjson 庫來簡化解析過程；又由於 pipeline 採用的是共享庫模式，所以需要過濾掉 pipeline 本身的項目地址，就是代碼中的 jenkins.git；剩下之後，去掉分支前綴 origin/，就是最後返回的分支信息。

ExtractNpmBuild

  獲取前端構建命令時，也是如此：區別就是請求地址改成 /config.xml，直接獲取 XML 配置，然後先通過 (?s)<script>(.*?)</script> 的正則提取 <script> 標籤內的 Groovy 腳本內容，再通過 npmRegex 正則提取構建命令。

自動重試機制

  藉著這次需求修改代碼的機會，結合實際工作中發現的問題，我順便加了個功能：研發有時候會一次性提交多個 Jenkins 構建請求，這就導致構建隊列堆積；因此，當研發需要構建時，先查看當前排隊的任務數量，如果排隊數量較少，就可以直接構建；反之，也不一棍子打死，在 1 分鐘內自動重試，實在不行的話再提示用戶稍後手動執行。
