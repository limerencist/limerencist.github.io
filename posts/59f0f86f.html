Golang 之 cobra

更新於2025-05-17|dev
|字數統計:2k|閱讀時間:8分鐘|瀏覽量:

  相信很多人剛接觸容器的時候，都有一個蛋疼的地方：**就是怎麼確認容器內和其他環境是連通的？** 而第一反應就是 ping、telnet 測試一下。很可惜，大部分的鏡像裡都不包含這些命令，要是安裝又顯得過於麻煩，怎麼辦？

  很明顯，這次的目標是要冩一個 cli 指令集，還要涉及到一些常用的參數（這個我會，上次就用 flag 包解析）。flag 可以，不過過於簡陋。
有沒有像 python 裡的 click 一樣好
用的工具呢？

  這麼問那當然肯定有啦！掌聲有請這次的主角——cobra 閃亮登場！

  怎麼樣？是不是從樣子上很符合常見的 cli 工具。有命令的用法，有參數的說明，有標誌的解釋。然後再往代碼倒推：至少有 2 個重要相似的地方：

&cobra.Command

  定義一個 cobra.Command 結構體，裡面的字段不就是執行之後看得的內容嗎？

func init()

  每個 go 文件都有 init 初始化函數，內容不同而已，比如 root.go 裡 init（）就沒有內容：也可以理解，root 命令可以理解為文件名本身，跟 shell 裡的 $0 類似；telnet.go 裡就有點不一樣了：

  很明顯，rootCmd.AddCommand(telnetCmd)，是把 telnet 子命令加入到根命令裡；

  後面的 telnetCmd.Flags() 則是給子命令添加相應的標誌：既然是 telnet ，肯定需要 主機 和 端口，因此通過 telnetCmd.MarkFlagRequired 把這 2 個作為必選項，再用 telnetCmd.MarkFlagsRequiredTogether 綁定必須同時使用;

  當然如果不想這麼做，也可以設定默認值 telnetCmd.Flags().StringP("machine", "m", "127.0.0.1", "machine"),這樣不傳入 -machine 或 -m 傳入主機信息，就默認本機；

  那聰明的人肯定要問了，如果設置並傳入對應的信息，怎麼再程序裡接收呢？很簡單，還是在定義 xxxCmd
的結構體裡，只要冩出 Run 方法；

先歸納一下

 通過以上內容可以看出 ，cobra 類似於框架：只要遵守它預先設定的一些規則，比如 xxxCmd 、 init() 、 xxxCmd.Flags() ,就能快速實現一個 cli 工具，剩下的就是編冩自己代碼的邏輯。

 等等，cli 裡常見的 help 功能、version 版本信息、命令推薦 也有嗎？作為一個成熟的框架，這種基礎哪能不具備啊，而且還是自動生動的。當然，要是對自動生成的不滿意，也可以自定義——不過對我沒有必要，已經夠用就不去瞎折騰了。

最後的總結

 cobra 的功能其實非常強大，看看 Docker、Kubectl 命令就知道了。我這裡只是初窺門徑，試試皮毛，畢竟有需求才有動力，而現在只要能滿足基本需求就已經足夠。等後面有新的想法，再去挖掘一點新內容。
