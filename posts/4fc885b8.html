K8s 部署方式簡介

更新於2023-02-09|devops
|字數統計:1.4k|閱讀時間:4分鐘|瀏覽量:

 如今 Kubernetes 可謂是最為火熱的雲原生技術，即使沒有用過，也一定聽過這個名詞。而對於運維而言，已經基本成為行業要求的剛需。不要求精通（畢竟任何技術都有一定的要求），但必須掌握基本原理、部署及基本使用。之前也冩過 K8s 的部署手冊，自我學習的兩三年過去，對此有了更深的一些體會，整理如下。

原生方式

Minikube/Kind

  此類方式只適合學習環境快速接觸 K8s，瞭解即可。

二進制

  安裝部署的主要過程如下：

  1. 初始化機器
  2. 生成證書及完成自籤
  3. Etcd 節點通過二進制文件（系統服務）部署 etcd
  4. Master 節點通過二進制文件（系統服務）部署 Apiserver、Controller、Schedule 等組件
  5. Node 節點通過二進制文件（系統服務）部署 Docker、Kubelet、kube-proxy 等組件
  6. 添加 CNI 插件

  詳細的部署過程可以參考拙文 通過二進制方式部署 Kubernetes 集群

Kubeadm

  安裝部署的主要過程如下：

  1. 初始化機器
  2. 所有節點先安裝 Docker、Kubeadm、Kubelet 等組件
  3. 使用 Kubeadm 初始化，自動添加證書，使用容器化部署 Etcd、Apiserver、Controller 等組件（這一步其實也需要區分節點類型，只不過都是 Kubeadm 簡單化了）
  4. 添加 CNI 插件

  詳細的部署過程可以參考拙文 通過 Kubeadm 部署 Kubernetes 單主多從集群 和 通過 Kubeadm 部署 Kubernetes 高可用集群

  需要注意的是，K8s 從 V1.24 版本開始移除默認對 Docker 的支持，使用 Containerd 的方式，冩這幾篇部署文檔時候還沒有出現這種情況，仍以 Docker 為主，後續看個人情況是否進行完成，所以僅供參考

總結

  • 通過 Kubeadm 可以簡單、快速地搭建 K8s 集群，易於添加/刪除節點，但是封裝成容器對應用者屏蔽一些底層的邏輯。
  • 通過二進制部署比較麻煩，卻更好地瞭解每一個步驟及組件的作用，有利於後續出問題時的排查。
  • 對於集群高可用即多個主節點的情況，也需要手動完成額外操作。

優化方式

  對原生的方式，個人或團隊進行優化（比如國內鏡像地址）和自動化封裝，包含且不限於基於二進制的 Kubeasz 和基於 Kubeadm 的 Kubeadm HA

  此類工具一般具有以下特點：

  • 支持離線化部署
  • 利用 ansible-playbook 實現自動化，既可以一鍵安裝，也可以安裝各個組件
  • 組件可選化，比如 Docker/Containerd，Calico/Flannel 等
  • 適配多個操作系統和 CPU 架構
  • 較為新的版本，高於 V1.20、V1.22

總結

  此類工作一般具有以下特點：

  • 開箱即用
  • 提供可視化的安裝界面，降低部署難度
  • 部署完成後默認自帶或可以安裝對應的 Dashboard，Dashboard 支持管理多集群
  • 需要考慮開源性及是否商用

封裝容器

  可以看出，從原生方式到企業級應用，部署 K8s 的過程，是一步一步封裝、簡化、豐富的。那麼，容器化的思想更近一步，把這個 K8s 集群當做一個整體，便是 sealos 和 sealor 主要做的事情。省去了大部分的步驟和配置，以鏡像的方式，只需幾條命令便可以構建一個 K8s 集群。

  不過，越是傻瓜的操作，意味著內部封裝的程度越高，越不容易接觸到裡面的核心。不出問題還好，出了問題又不清楚原理，簡直無從下手。況且這種方式遠沒有基於/改造原生方式成熟，慎用。

雲服務

  除了自己搭建 K8s 環境外，也可以使用雲廠商提供的服務，且不需要提前規劃服務器節點(之前的方式都需要區分節點角色)。總的來說大差不差，都是雲廠商有底層的硬件和技術支撐，花錢買服務就行了。

騰訊 TKE

  在我學習 K8s 集群的初期，常常看到 開發 Kubeadm，運維二進制 的說法。不論以何種方式，部署只是第一步，學習之路，道阻且長。從這幾種方式來看，技術都是一步一步完善的，善於利用並藉鑑已經成熟的東西，亦不失為一種好的學習方法。
