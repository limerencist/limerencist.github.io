推薦兩款實用的 Hexo 工具

更新於2025-06-28|plus
|字數統計:926|閱讀時間:3分鐘|瀏覽量:

  很久之前就是用 Hexo 部署了自己的博客，而想當初選擇 Hexo 的原因，詳見 搭建Hexo博客，但是最近發現有點太硬核，不是說 Hexo 本身變得複雜，而是整個博客發佈的模式過於繁瑣。我現在的模式是：

  • 本地 git clone 了 hexo 的博客目錄，使用 vscode 打開整個目錄；
  • marktext 新建編輯 md 文件，編輯後拿 vscode 對比 源文件和渲染後的文件 檢查是否格式錯誤；
  • vscode 打開終端使用 hexo s / hexo d / hexo g 檢閱並推送、部署；

  痛點有二：

  1. 編輯 md 文本比較麻煩，主要是 hexo 本身的 front-matter，比如 date 和 update 這兩個值，本地很難精確冩出；
  2. 雖然我不介意使用命令行去部署到 Github Page，但是操作久總是有點厭倦，說得直接一點就是現在我想偷懶；

  有沒有什麼方法可以更方便地編輯文章，又或者是簡化一下部署流程，解放我的雙手和鍵盤呢？

  強大的互聯網上當然是什麼都有，在試用幾款組件後，我推薦 覺得 Qexo 和 Hexon 都還不錯，因此話不多說，立馬開幹！

Qexo

一句話總結: UI 好看的功能強大型編輯器！

  參考官網文檔，先部署一下，我這邊使用的是 docker

  打開 管理頁面 自然是先配置，按照 圖 和 官方文檔 的指引就好，稍微麻煩一點就是 先生成 github 的 token，再配置 倉庫名等 信息，完成以後就 OK 啦！

  進入管理頁，好了，這個 UI 確實很舒服，是我的菜。

  喲，還可以改 hexo 的配置文件。

  新建個文檔看下效果吧。

  發現一個有意思的功能，可以直接預覽各個終端的效果。

  編輯後記得發佈，但要是注意，**這個發佈並不是發佈到 github page，而且直接在 git 裡添加這篇文件**，所以還是要執行 hexo 相關部署操作的哦！

Hexon

一句話總結: 從編輯到部署之 Hexo 一條龍！

  打開官網，先根據 ReadMe 一通安裝、配置的操作後

  完成後輸入剛才設置的用戶名密碼登錄 Hexon 的後臺管理頁面

  第一次打開的話最好 從GIT同步 一下

  來新建和編輯文檔吧，吐槽一下編輯頁只有 md 的源代碼模式，渲染效果得從外面看，但是右邊能處理 front-matter 信息


  完成之後當然是要部署和發佈的

  這邊由於之前啟動是前臺運行的，可以看到日誌就是在執行 hexo g / hexo d 的操作


  瞧！這不就完成了！

總結

 對比一下兩款產品，Qexo 重在文檔，可以把它當一個在線的 markdown 編輯器，還能始終保持 Github 上的博客源文件是最新的；而 Hexon 雖然編輯差一點（這時候就考驗 markdown 語法的掌握程度），優勢的地方在於簡化 Github Page 的部署和發佈流程。不過，說到底都是工具而已，適合自己的才是最好的。
