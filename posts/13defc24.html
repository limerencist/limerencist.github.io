TG 機器人，我來了！

更新於2026-06-09|dev
|字數統計:2.8k|閱讀時間:12分鐘|瀏覽量:

  入職沒多久，都還沒有熟悉公司運維的各個環境呢，就接到領導安排的開發任務：畢竟面試時候也問過相關的問題，比如常用編程語言等，估計也是想借此看下我的實際水平。恰好，需求的內容也是之前沒有接觸過的領域，我也能通過這次編程學到新的內容。

先思後行

  一陣簡單的需求分析之後，基本的操作流程如下：

  • 創建機器人
  • 獲取消息文件
  • sql 簡單校驗
  • 數據庫執行
  • 回覆輸出消息

創建機器人

 這一步其實沒啥特別要說的，根據網上的教程，Telegram 添加 @BotFather 的官方賬號，發個 /start 的消息再按照一步步提示就行，最為重要的是獲取機器人的 token，當然如果剛開始沒記錄後面再執行相關命令也可以重新獲取

Python 版

 由於我剛來，暫時還是以熟悉各個環境為主，真正需要工作的地方不多，所以時間比較充裕。聊了一下發現坐我左邊的同事使用的是 python，我也想順便複習一下 python，就又冩了一遍代碼。這次選擇 python-telegram-bot（PTB）——這絕對是我在網上找資料時看到最多使用的庫。既然之前的邏輯梳理查不多，這裡就直接上代碼：

 在自己手搓和 Google AI 的協助下，完成了上面的代碼，不過有以下幾點不同：

  1. 之前的 Go 代碼是直接對機器人發送消息的，只要有文件上傳就會執行程序；這次把機器人拉到群組裡，只有在發送文件後並@機器人才會執行程序，這樣也比較合理，能夠更精確地定位信息；
  2. PTB 裡已經封裝 get_file() 的方法，大大簡化 Go 裡獲取通過 fileID 獲取文件的步驟（畢竟 python 的優點之一就是封裝很多實用的方法，輪子夠多）；
  3. sql 的校驗進行優化，如果文件裡包含多個語句，現在也能執行；
  4. 在 AI 的建議下，將整段代碼封裝為 class，方便後續調用和維護；
  5. 考慮到代碼實現比較重要，就簡化一些文本輸出樣式；

殊途同歸

 雖然使用的編程語言不同，但在需求和邏輯的規定下，代碼層面沒有太大的區別，無非是一些 API 或者輪子方法的使用上。而且，瞎說句大實話，現在冩程序都用 AI，又不是十分核心的業務，都是些簡單的工具，想法比代碼重要。在和 AI 的對話中，還能不停發現新的問題或優化點，促使代碼冩得更好。
